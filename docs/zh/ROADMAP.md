# 路线图

计划中的工作，以及本库目前有哪些限制。这里没有哪一项承诺了某个版本。

## 计划中

| 工作 | 为什么 | 备注 |
| --- | --- | --- |
| 用同一批页面做出带标签页的设置窗口 | 有些应用想要系统设置旧的 `TabView` 版式，又不想再弄一套页面模型 | 在 `[SettingsPage]` 和同一个 detail 闭包之上再加一种窗口 |
| 行上的标记 | 页面标题旁边的未读数和“新”标记 | 一个 `SettingsPage` 属性，画在行里标题的旁边 |
| 运行时按权限隐藏页面 | 页面藏在登录或功能开关之后 | 目前：构建窗口时不要那一页，或者让页面自己说明该怎么办 |
| 创建之后更换页面 | 窗口对象已经存在之后才加载的插件 | `sections` 目前是固定的；加一个 setter 就得让侧边栏视图跟着变 |
| 跟随应用内切换语言 | 不重启就换语言的应用 | 窗口把 locale 应用到侧边栏、标题、工具栏和本库自带的文字上 |
| 页面头部藏起标题 | 页面开头是一块带页面名字的大头部，像系统设置的“通用”那样，工具栏里不再重复显示名字 | 试过，先搁下了：标题藏起来时，AppKit 的自动工具栏样式会变成紧凑（macOS 15 上从 52 pt 变成 38 pt），标题一回来页面就跳一下。要做成得固定工具栏样式，还要在 macOS 26 和 27 上验证 |

## 已知限制

| 限制 | 详情 |
| --- | --- |
| macOS 14：工具栏下方的分隔线始终显示 | 系统设置是页面滚动之后才显示它；macOS 15 之前 SwiftUI 不上报滚动位置（[ARCHITECTURE.md](ARCHITECTURE.md#工具栏下方的分隔线)） |
| macOS 14 上什么都不跑 | 本库为部署目标 14 构建，`#available` 分支也保持精简，但 GitHub 在 2026-11-02 停用了 `macos-14` runner，也没人手工验 14，所以这条路径没有测试 |
| 配置按窗口对象固定 | `size`、`resizing`、`sidebarWidth`、`search` 等都在构建窗口时读取。要改就新建一个 `SidebarSettingsWindow` |
| 普通 `ScrollView` 页面在 macOS 14 和 15 上工具栏更浅 | AppKit 只会把工具栏背景对齐到表单或列表的滚动视图，不对齐普通 `ScrollView`。页面请写成分组表单 |
| macOS 27：关掉按钮后的标题还没检查过 | 从 macOS 26 起，本库不再挪动标题，AppKit 放哪儿就是哪儿；26 上它和页面的表单对齐，27 上还没人看过 |
| 应用内切换语言只能到达页面 | 侧边栏标题、窗口标题和本库自带的文字会停在启动时的语言，直到重启。应用在 `detail` 里应用自己的 locale 时，页面才跟着变 |
| 没有自定义的选中形状 | 选中块是系统侧边栏的，纯色或方块；自己画一个会丢掉按字选择和旁白的列表导航 |
| 不支持 `SettingsLink` | `SettingsLink` 和 `openSettings()` 打开的是 `Settings` scene，不是这个窗口；用 `show(page:)` 或 `OpenSidebarSettingsButton` |
| 页面不能在窗口里预览 | 单独预览页面的视图，把它固定到一个 frame 上 |
